# Issue #1: 独立実行による意味評価

[Issue #1](https://github.com/Olein-jp/personal-agent-skills/issues/1)の評価記録。作業中の1.1版をファイル単位のSHA-256で固定し、開発会話・既存の期待結果・過去レポートを渡さない3つの新しい会話で、4本の合成原稿をAUDITした。BとDだけは同じ評価者が別々に実行した。

## 結果

| ケース | 種類 | 初回JSON | 正式JSON | 初回と正式の差 |
|---|---|---|---|---|
| A | 集客・相談型 | 合格 | 合格 | なし |
| B | 技術解説型 | 合格 | 合格 | なし |
| C | 比較・意思決定型 | 合格 | 合格 | なし |
| D | 技術解説型・機能組み合わせの条件不足 | 合格 | 合格 | なし |

固定入力・スキルのハッシュも変わっていない。意味判断をJSON検証の合格に合わせて書き換える工程はなかった。今回の評価でスキル本体を追加修正する根拠は確認していない。

意味上の判定と集計は、利用者が原稿・根拠・R01〜R08・重複指摘の整理を確認して承認した。

- 既知の問題2件: 正しい指摘2件、見落とし0件。
- 問題でない3条件: 誤検知0件。
- 妥当な判断不可・確認待ち: 5件 (Dの実現条件1件、4原稿の実成果各1件)。
- 個別仕様と組合せ案の実現条件の区別: 1件。

Aの9項目の改善推奨は、同じ保証と危険手順の2つの問題への関連・重複指摘であり、9個の別問題として数えていない。誤検知0件は3つの負例条件の範囲に限定する。全項目に対する精度100%・母集団の再現率・実務品質の保証ではない。

## 追跡用ファイル

- [manifest.json](manifest.json): 評価版と原稿・依頼・一次資料のハッシュ、URL、取得時刻。
- [run-conditions.json](run-conditions.json): 役割、読取/書込範囲、渡した資料と除外した情報、独立性の限界。
- `inputs/case-a`〜`case-d`: 新しく作成した原稿と依頼。外部の公開記事を書き換えたものではない。
- `results/a`〜`d`: 各初回JSON、正式JSON、Markdownレポートと検証ログ。
- [reference-review.json](reference-review.json): 参照基準と根拠・対象箇所。
- [adjudication.json](adjudication.json): 人の確認を経た意味上の判定と集計単位。
- [human-review.md](human-review.md) / [human-review-record.json](human-review-record.json): 人が確認した資料と承認記録。
- [verification.json](verification.json): 機械的な形式・参照・固定入力検査。意味の正しさを自動認定するものではない。

## 検証と再実行

この評価のJSONは依存関係を導入したPythonで、次のように検証できる。

```bash
python3 olein-content-conversion/scripts/validate-audit.py evaluations/olein-content-conversion/issue-1-independent-2026-10-30/results/a/audit-result.json
```

b/c/dも同様。コードや共有スキーマの追加変更はないため、この評価では全体テストを無意味に繰り返していない。

新しい評価を行う場合は、スキル・ケースごとの依頼と原稿・必要な一次資料だけを新しい実行へ渡す。このREADME、参照基準、既存結果、人によるレビューは評価終了まで渡さない。別の資料・時点・スキルを使うなら別の実行記録を作り、今回の結果を上書きしない。

## 限界

4つの合成原稿、同一モデル系列、1回ずつの小規模評価である。参照基準案は開発文脈を知る親Codexが用意し、利用者が結果とともに確認した。完全に独立した人が一から作成した正解セットではない。

評価者には新しい会話と許可する読取範囲を与えたが、共有ファイルシステムをOSで分離してはいない。指示外アクセスの完全な検出やモデル内部知識の分離を保証しない。原資料のHTMLは取得済みの一時スナップショットで、長期保持を保証しない。URL・取得時刻・ハッシュを保存しており、新たに取得した内容を同じ資料版とみなしてはならない。

記事・本番サイト・フォーム・分析設定を操作していない。実装の動作、現在の外部表示、実際のSEO/CV成果、PLAN/REVISEの実務品質は今回の認定対象ではない。
