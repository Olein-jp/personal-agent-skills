# 試験導入の確認・指摘記録

必要な指摘について以下の1件分をコピーして記入する。原文・根拠の詳細は参照先に保持し、顧客情報や実測データ全体を複製しない。合成の記入練習なら「合成・運用実績ではない」と明示し、実記事の記録と分ける。

## 1件分の雛形

| 項目 | 記入欄 |
| --- | --- |
| 記録の種類・確認日・確認者 | 実記事レビュー / 合成の記入練習 / 未記入 |
| 原稿の参照先・版 | 保存先またはURLと、SHA-256等の版識別子 |
| スキル版 | コミット、schema_version、rules_version |
| 元監査・指摘ID | 保存先とB-01等。部分確認ならE-03.submission等。見落としは「監査に未記載」と適用ルールIDを記す |
| 記事目的・原文位置・重要度 | 対象読者、目的、該当節、元監査の重要度と人による確認結果 |
| 根拠と未確認範囲 | 根拠ID・資料の参照箇所、観測内容、適用条件、残る不明点 |
| 評価区分 | 誤検知 / 見落とし / 妥当な判定不可 / 妥当な指摘 / 妥当な要確認 / 評価中 |
| 利用者判断・理由・判断の記録 | 採用 / 保留 / 棄却。何の判断・提案・差分に対する採否かと、理由・確認者・日時や承認記録の参照先 |
| 対応状況・残る作業 | 未着手 / 調査中 / 差分案保存済み / 反映済み / 対応不要等。実施範囲と次の確認条件 |

評価区分、採否、対応状況は独立して記録する。例えば「妥当な判定不可」を採用しても「実測確認済み」にはしない。見落としは適用ルールと具体的な原文・根拠から判断し、単に項目が未記載だからと認定しない。誤検知・見落としの証拠が揃っていなければ評価中とする。

REVISEがある場合は、差分の保存先・before/afterの位置・対応指摘IDと差分ごとの採否を「利用者判断」「対応状況」に追記する。採用済みでも反映・公開前なら、その状態を残す。
