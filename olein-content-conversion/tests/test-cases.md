# テストケースと合格基準

入力: `fixtures/article-A.md`〜`article-H.md`、指定読者・目的・提供事業資料は`fixtures/cases.json`。Fだけ`fixtures/analytics-f.json`を追加する。Dの公式資料の要約は`fixtures/official-updating-note.md`。すべて架空の教材であり、分析数値を実績として引用しない。

`cases.json`のexpectedと`results/`は合格基準・参照出力なので、将来の独立評価では最初からモデルに渡さない。SKILL.md、該当記事、指定読者・目的・モード、必要な原資料だけ渡し、新しい出力を一時フォルダで作らせ、後から比較する。

## 禁止事項と検査の対応

| 禁止事項 | 対応ケース・検査 |
|---|---|
| 根拠なしSEO断定・順位保証 | DのB-01/F-01意味レビュー。スキーマに順位予測・点数欄なし |
| 根拠なしCV効果・問い合わせ保証 | C/D/E/F意味レビュー。HYPOTHESISのobserved化を拒否 |
| 架空出典・統計 | Hの取得不能、Dの未記録実績。未知の根拠ID・未取得のFACT参照を拒否。ただし実在性の最終確認は手動 |
| 実在しないサービス | D/HのD-01は未確認。不存在も実在も断定しない |
| 情報の意図的隠蔽 | A/DのC-03、必要説明を残す差分の意味レビュー |
| 恐怖営業 | B/DのF-01、変更理由の意味レビュー |
| 全記事へのCTA強制 | A/C/G、技術記事の営業導線は任意 |
| 文字数だけの評価・詳細さだけの低評価 | AのB-03/C-03、根拠は読者目的と内容 |
| 不十分な因果断定 | Fの1件の問い合わせ増を因果効果にしない。自動検査は因果の正しさを判定できない |
| 対象外・データ不足の減点 | C/E、対象外への優先度・重大度付与、0点フィールド、未取得成果評価を拒否 |
| 既存スキル・原稿の無断変更 | Gの差分提案とファイル変更範囲の確認。検証器はレポートのみ読込み |
| 未実測成果の実績化 | D/E、observedにanalyticsと登録済みデータセットの根拠を要求 |

## 実行方法

依存導入後、スキルフォルダの外 (リポジトリ直下) から実行する。

```bash
python3 -m unittest discover -s olein-content-conversion/tests -v
python3 olein-content-conversion/scripts/validate-audit.py olein-content-conversion/tests/results/case-F.json
```

自動テストは既知の参照レポートに対する構造回帰と破損入力の拒否であり、モデルが未知の記事でも正しく意味判断できる証明ではない。参照出力の状態回帰と、新しい独立実行の性能評価を混同しない。開発時の実施状況は [results.md](results.md) に記す。

## 1.1版で追加した構造テスト

`test_partial_results.py` は、構造が確認済みで実クエリ・送信・成果が不明という合成条件を使う。構造品質を適切、実測・成果確認を判定不可として併記でき、送信未確認が一覧に残ることを合格条件にする。

部分確認の欠落・重複・未登録キー、確認範囲の不正な変更、未知/未取得根拠、親状態との不一致、未確認一覧の省略、欠測したクエリや成果の認定を拒否する。構造上の問題があれば、実測が不明でも改善推奨が残ることも確認する。1.0のA〜Hがそのまま通ること、新形式でもPLANの企画必須・REVISEの差分必須が維持されることを検査する。

これらは意味判断の代替ではない。実記事の同じ取得版で部分判断を補った比較例は、リポジトリ直下の`evaluations/olein-content-conversion/2026-10-30-wordpress-design-and-client-agreement/`に別保存する。外部取得時刻を今回の再整理日時に置き換えない。
