# Editorial Readability

## 基本方針

- AIらしさの隠蔽ではなく、人間の読解特性に沿った可読性の改善を目的にする。
- 原則として全文を書き直さない。問題のある意味単位を特定し、必要な箇所だけ編集する。
- 次の優先順位を守る。
  1. 事実の正確性
  2. 筆者が意図した意味
  3. 筆者の判断と立場
  4. 確立済みの筆者文体
  5. 人間にとっての読みやすさ
  6. 一般的な文章作法
- 読みやすさのために、事実、留保条件、専門的な精度、筆者固有の判断を削らない。
- 原稿にない事実、経験、感情、意見、具体例を作らない。具体化に情報が必要なら、不足を示すか確認する。
- 語句の禁止リストや機械的な文字数基準を使わない。各変更は文脈上の理由で判断する。

## 編集モードを決める

- **直接編集**: 書き直しや修正を依頼された場合に使う。原稿または対象ファイルへ必要最小限の変更を加える。
- **レビューのみ**: 診断、評価、改善提案を依頼された場合に使う。原稿を変更せず、優先度の高い問題と修正方針を示す。
- **構成編集**: 読者の疑問順と説明順が大きくずれている場合に使う。段落や節の移動が必要な理由を確認し、許可された範囲でだけ再構成する。

依頼が曖昧な場合、貼り付けられた文章には編集案を返し、リポジトリ内のファイルは明示的な変更依頼があるときだけ編集する。

## ワークフロー

### 1. Preserve

編集前に次を短く把握し、変更禁止事項として保持する。

- 中心主張と記事の目的
- 事実、数値、引用、出典との対応
- 筆者の判断、推奨、留保、確信度
- 読者と前提知識
- 一人称、語調、リズムなどの文体的特徴
- 専門用語と意味上必要な反復

筆者文体を指定する別スキルがある場合は、そのスキルを先に適用した原稿を編集対象とする。`$olein-writing-style` と併用するときは、同スキルの文体、表記、経験の扱いを優先する。

### 2. Diagnose

`references/editing-model.md` を読み、次の7軸で問題箇所を診断する。

1. Redundancy: 同じ意味の不要な反復
2. Density: 一度に処理する情報量
3. Complexity: 構文と意味統合の負荷
4. Predictability: 論点と展開の追いやすさ
5. Specificity: 抽象表現の指示対象
6. Variation: 内容に応じた文長・段落・構文の変化
7. Voice: 筆者の判断と立場の保持

AI生成文らしい傾向が問題になっている場合は、`references/ai-writing-patterns.md` も読む。文章全体に一律の修正をかけず、読解を妨げる箇所だけを編集対象にする。

### 3. Edit

- 削除、局所的な言い換え、文の分割・結合、段落内の順序調整、段落移動の順に、影響の小さい手段から試す。
- 接続詞は、削っても論理関係が分かる場合だけ省く。
- 抽象語は、原稿内に根拠となる情報がある場合だけ具体化する。
- 文長や段落長はランダム化しない。重要度、説明量、強調の必要性に応じて変える。
- 箇条書きは、比較、手順、独立項目の走査性が上がる場合に使う。連続した論旨は文章へ戻す。
- 「一文一情報」「一段落一文」などへ機械的に統一しない。読者が意味を保持し、統合できる単位に整える。
- 元の判断が強い箇所を、無難な両論併記へ戻さない。元に判断がない場合は、勝手に追加しない。

### 4. Re-read

修正箇所だけでなく、前後の段落を含めて通読する。次を確認して必要なら一度だけ調整する。

- 話題の移動を追えるか
- 削除によって前提や指示対象が失われていないか
- 局所編集の継ぎ目が不自然でないか
- 文長、段落長、構文が内容に反して均一になっていないか
- 結論やまとめが本文を重複していないか

### 5. Verify

原稿と編集後を比較し、次を満たすまで完了としない。

- 主張、事実、因果関係、条件、確信度が変わっていない。
- 筆者の判断と固有の文体が薄まっていない。
- 新しい事実、経験、意見を追加していない。
- 必要な専門用語、引用、リンク、表記を保持している。
- 変更していない箇所まで無用に言い換えていない。
- 編集後の文章が一度の通読で追え、要点を頭の中で再翻訳する負担が減っている。

研究上の背景やルールの由来を説明する必要がある場合だけ、`references/research-foundations.md` を読む。研究知見を個別原稿への万能な判定基準として扱わない。

## 出力

直接編集では、編集後の本文を先に示す。説明を求められた場合、または意味に影響し得る変更がある場合だけ、主な変更点と未解決の確認事項を簡潔に添える。

レビューのみでは、指摘を重要度順にまとめ、各項目に対象箇所、読解上の問題、最小の修正方針を示す。単語の出現だけを根拠に「AIっぽい」と判定しない。
